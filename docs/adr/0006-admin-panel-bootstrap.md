# ADR 0006: 操作面板一次性引导凭据

- Status: Accepted
- Date: 2026-08-31

## 背景

`relkit-serve` 的 `/-/admin`（及 `/-/p/`、`/-/admin/files`）是给这台箱的运营看的现算面板，不是对外目录。此前无鉴权：知道 URL 就能看发布树索引。

候选做法里，有两件不能做：

1. **把管理员口令写成全局固定配置、存进 Dec user 平面。** user 平面不能按项目切分；而且面板口令是**这台实例**的运营凭据，不是产品身份，也不该进各产品仓库的 `.secrets/project/`。
2. **默认账号 + HTTP 首次设置向导。** 谁先打开页面谁就是管理员。内网 URL 会被书签、转发、扫描。

上传 token（运营方 / 产品）仍然只能 `PUT` 发布树，不是管理口令。签发、列举、吊销 token 继续只走 SSH + 本机 `init`（见 AGENT-GUIDE §2.3.1）。

## 决策

1. **每台实例在 `init` 时自己生成一张一次性引导凭据。** 盘上只存 sha256，明文只打印一次（`RELKIT_ADMIN_BOOTSTRAP`）。不要备份进 Dec：它被设计成用完即废。
2. **有引导凭据且还没有运营账户时，才能在 `/-/admin/setup` 创建第一个管理员。** 账户写入与引导哈希清空是同一次落盘。此后即使旧明文还在，HTTP 也必须拒绝再开户。
3. **日常登录是用户名 + 密码 + 签名 cookie。** 不设默认口令。数据面（`/`、`browse/`、协议对象、`/-/latest/`）保持匿名。
4. **破窗是 SSH：`relkit-serve init -reset-admin`。** 作废现有账户与 session，再发一张引导凭据。忘密码、唯一管理员走了，都走这条，不走 HTTP。
5. **状态文件默认在服务目录** `<dir>/.relkit-serve-admin.json`（0600，不出现在列表、GET 404、PUT 拒绝），与下载计数同一理由：默认 systemd 单元只允许写发布树。不要为了写账户去打开整个 `/etc/relkit-serve`（那里有上传 token 明文）。

引导凭据**不是**常驻管理 API，也**不是**上传 token。有它只能在「管理员人数 = 0」时开出第一个账户。

## 后果

- 新装必须先 `init`、再打开 `/-/admin` 用打印出的引导码建账户；自检里未登录的 `/-/admin` 是 302，不再是 200。
- `-token-only` 只轮换上传 token，不动面板。`-force` 会连引导凭据一起重签。
- 进程被攻破后仍能改服务目录里的账户文件——那和个人能改发布树是同一等级的失败；不因此把 token 目录写成可写。
- 单人运营箱先只支持一个管理员账户。多账户以后再加，不要为此做「未初始化 HTTP 向导」。
